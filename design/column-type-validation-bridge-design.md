## 1. 背景与动机

### 1.1 两套并行的验证体系

当前系统中存在两套独立的数据验证机制：

| 维度 | `src/types`（列类型系统） | `src/plugins/data-validation`（验证插件） |
|------|--------------------------|------------------------------------------|
| **验证时机** | 编辑器提交时（`validateCellValue`） | `BEFORE_SET_VALUE_AT` 钩子拦截 |
| **验证来源** | 列配置 `columns[].type` + `options` | 显式规则 `setValidation()` |
| **验证方式** | `BaseColumnType.validate()` | `ValidationEngine.validateCell()` |
| **约束表达** | `options.min/max/maxLength/source` | `ValidationRule.operator/value/source` |
| **错误处理** | 返回 `true/false/string` | 返回 `ValidationResult` 对象 |
| **UI 反馈** | 编辑器内联提示 | Portal 气泡 / 条件格式 |
| **作用范围** | 列级或单元格级 | 任意区域（range） |
| **持久化** | 随 `columns` 配置 | 随 `ValidationRule` 导出 |

### 1.2 约束重叠示例

```javascript
// 列类型方式 — 在 columns 配置中
columns: [{
    type: 'numeric',
    options: { min: 0, max: 100 }  // ← 列类型自带的 min/max
}]

// 验证插件方式 — 显式规则
dv.setValidation({
    range: 'A:A',
    type: 'number',
    operator: 'between',
    value: [0, 100]                // ← 验证规则的 min/max
})
```

**两者功能完全重叠**，但走的是两条不同的代码路径，导致双重验证、错误信息不一致、配置冗余。

## 2. 问题分析

### 2.1 双重验证

当一列同时配置了列类型约束和验证规则时：

```
用户输入 150（列配置 max=100，验证规则 also max=100）

路径1: ColumnTypeManager.validateCellValue()
  → NumericColumnType.validate(150)
  → "数值不能大于 100"
  → 编辑器阻止提交

路径2: DataValidationPlugin.interceptBeforeSetValue()
  → NumberValidator.validate(150, rule)
  → ValidationResult.failure("...")
  → 钩子返回 false，阻止写入
```

同一个约束被检查两次，浪费性能且可能导致不一致行为。

### 2.2 错误信息不一致

- 列类型返回：`"数值不能大于 100"`
- 验证插件返回：`rule.errorMessage`（用户自定义或默认模板）

用户看到的错误提示取决于哪个拦截先执行，造成困惑。

### 2.3 拦截顺序不确定

列类型验证在编辑器层，验证插件在钩子层。两者执行顺序取决于编辑器实现，不可预测。

### 2.4 配置冗余

用户需要为同一个约束写两遍配置：

```javascript
// 当前：需要写两遍
columns: [{ type: 'numeric', options: { min: 0, max: 100 } }]
dv.setValidation({ range: 'A:A', type: 'number', operator: 'between', value: [0, 100] })

// 期望：只需写一遍
columns: [{ type: 'numeric', options: { min: 0, max: 100 } }]
// → 桥接器自动生成等价的验证规则
```

## 3. 设计目标

| # | 目标 | 优先级 |
|---|------|--------|
| G1 | **消除双重验证**：列类型约束自动生成验证规则，不再重复检查 | P0 |
| G2 | **单一配置源**：用户只需在 `columns` 中配置约束，桥接器自动同步 | P0 |
| G3 | **手动规则优先**：用户显式设置的规则优先级高于自动生成的规则 | P1 |
| G4 | **双向可追溯**：自动规则标记来源，可区分手动/自动，支持反向清理 | P1 |
| G5 | **实时同步**：列配置变化时自动更新验证规则 | P1 |
| G6 | **零侵入**：不修改现有 `BaseColumnType` 和 `ValidationEngine` 的核心逻辑 | P2 |

### 4.2 核心设计决策

#### D1: 桥接方向 — 列类型 → 验证规则（单向）

**选择**：列类型约束自动生成验证规则，而非验证规则反向生成列类型配置。

**理由**：
- 列类型配置是用户的**意图声明**（"这列是数字，范围 0-100"）
- 验证规则是**执行机制**（"对 A 列执行 number between 0 100 验证"）
- 意图 → 执行 是自然方向，反向则语义不明确

#### D2: 验证统一入口 — 验证插件

**选择**：桥接后，所有验证统一由 `DataValidationPlugin` 执行，列类型的 `validate()` 不再参与运行时验证。

**理由**：
- 避免双重验证
- 验证插件提供更丰富的功能（批量验证、条件格式、UI 反馈）
- 列类型的 `validate()` 保留用于编辑器层的即时反馈（输入时红色边框等轻量提示）

#### D3: 自动规则标记

**选择**：自动生成的 `ValidationRule` 带有 `metadata` 标记。

```javascript
rule.metadata = {
    source: 'column-type-bridge',  // 来源标识
    columnType: 'numeric',         // 原始列类型名
    column: 0,                     // 列号
    generatedAt: Date.now()        // 生成时间
};
```

## 5. 桥接映射规格

### 5.1 完整映射表

| 列类型 | 列配置 options | 生成的 ValidationRule | 条件 |
|--------|---------------|---------------------|------|
| `numeric` | `{ min, max }` | `{ type: 'number', operator: 'between', value: [min, max] }` | min 和 max 都存在 |
| `numeric` | `{ min }` | `{ type: 'number', operator: 'greaterThanOrEqual', value: min }` | 仅 min |
| `numeric` | `{ max }` | `{ type: 'number', operator: 'lessThanOrEqual', value: max }` | 仅 max |
| `select` | `{ source: [...] }` | `{ type: 'list', source: [...] }` | source 为简单数组 |
| `select` | `{ source: [{value, label}] }` | `{ type: 'list', source: [value1, value2, ...] }` | source 为对象数组，提取 value |
| `date` | `{ min, max }` | `{ type: 'date', operator: 'between', value: [min, max] }` | min 和 max 都存在 |
| `date` | `{ min }` | `{ type: 'date', operator: 'greaterThanOrEqual', value: min }` | 仅 min |
| `date` | `{ max }` | `{ type: 'date', operator: 'lessThanOrEqual', value: max }` | 仅 max |
| `text` | `{ maxLength }` | `{ type: 'text', operator: 'lessThanOrEqual', value: maxLength }` | maxLength 存在 |
| `textarea` | `{ maxLength }` | `{ type: 'text', operator: 'lessThanOrEqual', value: maxLength }` | maxLength 存在 |

### 5.2 不映射的列类型

以下列类型**不生成**验证规则（原因：无对应验证器或语义不匹配）：

| 列类型 | 原因 |
|--------|------|
| `hyperlink` | 无 URL 格式验证器（regex 验证器需用户自行配置 pattern） |
| `checkbox` | 布尔值无需范围验证 |
| `progressBar` | 渲染器类型，非数据约束 |
| `starRating` | 渲染器类型，非数据约束 |
| `sparkline` | 渲染器类型，非数据约束 |
| `colorPreview` | 渲染器类型，非数据约束 |

### 5.3 映射细节

#### numeric → number

```javascript
// 输入：列配置
{ type: 'numeric', options: { min: 0, max: 100, numericFormat: { pattern: '0,0.00' } } }

// 输出：验证规则
new ValidationRule({
    range: 'A:A',                    // 根据列号自动计算
    type: 'number',
    operator: 'between',
    value: [0, 100],
    errorMessage: '数值必须在 0 到 100 之间',  // 自动生成友好消息
    errorStyle: 'stop',              // 列类型的 min/max 默认为强制约束
    priority: 1000,                  // 自动规则优先级低于手动规则
    metadata: {
        source: 'column-type-bridge',
        columnType: 'numeric',
        column: 0,
        generatedAt: Date.now()
    }
})
```

#### select → list

```javascript
// 输入：简单数组
{ type: 'select', options: { source: ['男', '女', '其他'] } }

// 输出：
new ValidationRule({
    range: 'B:B',
    type: 'list',
    source: ['男', '女', '其他'],
    showDropdown: true,
    errorMessage: '请从下拉列表中选择有效选项',
    priority: 1000,
    metadata: { source: 'column-type-bridge', columnType: 'select', column: 1 }
})

// 输入：对象数组
{ type: 'select', options: { source: [{ value: 0, label: '好' }, { value: 1, label: '中' }, { value: 2, label: '差' }] } }

// 输出：提取 value 列表
new ValidationRule({
    range: 'C:C',
    type: 'list',
    source: [0, 1, 2],              // ← 提取 value，非 label
    showDropdown: true,
    errorMessage: '请从下拉列表中选择有效选项',
    priority: 1000,
    metadata: { source: 'column-type-bridge', columnType: 'select', column: 2 }
})
```

#### date → date

```javascript
// 输入
{ type: 'date', options: { dateFormat: { pattern: 'YYYY-MM-DD' }, min: '2020-01-01', max: '2030-12-31' } }

// 输出
new ValidationRule({
    range: 'D:D',
    type: 'date',
    operator: 'between',
    value: ['2020-01-01', '2030-12-31'],
    errorMessage: '日期必须在 2020-01-01 到 2030-12-31 之间',
    priority: 1000,
    metadata: { source: 'column-type-bridge', columnType: 'date', column: 3 }
})
```

#### text/textarea → text (length)

```javascript
// 输入
{ type: 'text', options: { maxLength: 50 } }

// 输出
new ValidationRule({
    range: 'E:E',
    type: 'text',
    operator: 'lessThanOrEqual',
    value: 50,
    errorMessage: '文本长度不能超过 50 个字符',
    priority: 1000,
    metadata: { source: 'column-type-bridge', columnType: 'text', column: 4 }
})
```

## 6. API 设计

### 6.1 ColumnTypeValidationBridge 类

```typescript
class ColumnTypeValidationBridge {
    /** 桥接器是否已激活 */
    #active: boolean = false

    /** 列类型管理器引用 */
    #columnTypeManager: ColumnTypeManager

    /** 数据验证插件引用 */
    #validationPlugin: DataValidationPlugin

    /** 自动生成的规则 ID → 列号 映射 */
    #autoRuleToColumn: Map<string, number>

    /** 列号 → 自动生成的规则 ID 映射 */
    #columnToAutoRule: Map<number, string>

    /** 列号 → 上次同步的配置快照（用于增量同步） */
    #lastSyncedConfig: Map<number, Object>

    /**
     * 构造桥接器
     * @param columnTypeManager - 列类型管理器实例
     * @param validationPlugin - 数据验证插件实例
     */
    constructor(columnTypeManager, validationPlugin)

    // ─── 核心方法 ───

    /**
     * 从列配置全量同步验证规则
     *
     * 遍历所有列配置，为有约束的列自动生成验证规则。
     * 已存在的自动规则会先移除再重新生成（确保与最新配置一致）。
     * 手动设置的规则不受影响。
     *
     * 调用时机：
     * - applyColumnsConfig() 后
     * - Sheet 切换后
     * - 桥接器初始化时
     */
    syncFromColumnConfig(): void

    /**
     * 同步单列配置变更（增量同步）
     *
     * 仅处理指定列的配置变更，不影响其他列的规则。
     * 适用于列配置局部修改的场景（如动态修改某列的 max 值）。
     *
     * @param col - 列号
     */
    syncColumn(col: number): void

    /**
     * 清除所有自动生成的验证规则
     *
     * 移除所有 metadata.source === 'column-type-bridge' 的规则。
     * 手动设置的规则不受影响。
     */
    clearAutoGeneratedRules(): void

    // ─── 查询方法 ───

    /**
     * 获取桥接状态信息
     *
     * @returns {Object} 桥接状态
     * @returns {boolean} returns.active - 是否激活
     * @returns {number} returns.autoRuleCount - 自动规则数量
     * @returns {number} returns.bridgedColumnCount - 已桥接列数
     * @returns {Object[]} returns.details - 每列的桥接详情
     */
    getBridgeStatus(): Object

    /**
     * 检查指定列是否有自动生成的规则
     * @param col - 列号
     * @returns {boolean}
     */
    hasAutoRuleForColumn(col: number): boolean

    /**
     * 获取指定列的自动生成规则 ID
     * @param col - 列号
     * @returns {string|null} 规则 ID，不存在则返回 null
     */
    getAutoRuleIdForColumn(col: number): string | null

    // ─── 生命周期 ───

    /** 激活桥接器 */
    activate(): void

    /** 停用桥接器（清除所有自动规则） */
    deactivate(): void

    /** 销毁桥接器（清除规则 + 解除引用） */
    destroy(): void
}
```

### 6.2 私有方法

```typescript
class ColumnTypeValidationBridge {
    /**
     * 从列类型配置生成验证规则
     *
     * 核心映射逻辑，根据列类型和 options 生成对应的 ValidationRule。
     * 如果列类型没有可映射的约束（如 hyperlink），返回 null。
     *
     * @param col - 列号
     * @param config - 列配置对象
     * @returns {ValidationRule|null} 生成的规则，无约束则返回 null
     */
    #generateRuleFromColumnType(col: number, config: Object): ValidationRule | null

    /**
     * 检查指定列是否已存在手动设置的同类验证规则
     *
     * 用于去重：如果用户已为某列手动设置了 number 类型规则，
     * 则不再自动生成 number 类型规则。
     *
     * @param col - 列号
     * @param validationType - 验证类型（'number'/'list'/'date'/'text'）
     * @returns {boolean}
     */
    #hasManualRuleForColumn(col: number, validationType: string): boolean

    /**
     * 将列号转换为列区域字符串
     *
     * @param col - 列号（0-based）
     * @returns {string} 列区域字符串（如 "A:A"、"B:B"）
     *
     * @example
     * this.#colToRange(0);   // "A:A"
     * this.#colToRange(25);  // "Z:Z"
     * this.#colToRange(26);  // "AA:AA"
     */
    #colToRange(col: number): string

    /**
     * 生成自动错误消息
     *
     * 根据列类型和约束参数生成用户友好的错误消息。
     * 消息格式与列类型 validate() 返回的格式保持一致。
     *
     * @param columnType - 列类型名称
     * @param operator - 运算符
     * @param value - 约束值
     * @returns {string} 错误消息
     */
    #generateErrorMessage(columnType: string, operator: string, value: any): string

    /**
     * 判断列配置是否有可桥接的约束
     *
     * @param config - 列配置对象
     * @returns {boolean}
     */
    #hasBridgeableConstraint(config: Object): boolean
}
```

## 7. 同步时机与生命周期

### 7.1 同步触发点

| 触发点 | 同步方式 | 调用方法 |
|--------|---------|---------|
| `applyColumnsConfig()` 后 | 全量同步 | `syncFromColumnConfig()` |
| Sheet 切换后 | 全量同步 | `syncFromColumnConfig()` |
| 单列配置动态修改 | 增量同步 | `syncColumn(col)` |
| 桥接器初始化 | 全量同步 | `syncFromColumnConfig()` |
| 桥接器停用 | 清除 | `clearAutoGeneratedRules()` |

### 7.2 全量同步流程

```
syncFromColumnConfig()
        │
        ↓
  ┌─ 遍历所有列配置 ──────────────────────────────┐
  │                                                │
  │  对每列 col:                                    │
  │    1. 读取 columnsConfig.get(col)               │
  │    2. 检查是否有可桥接约束                       │
  │       ├─ 无约束 → 跳过                          │
  │       └─ 有约束 → 继续                          │
  │    3. 检查是否已存在手动同类规则                   │
  │       ├─ 存在 → 跳过（手动优先）                 │
  │       └─ 不存在 → 继续                          │
  │    4. 检查是否已有自动规则且配置未变               │
  │       ├─ 未变 → 跳过（避免重复生成）             │
  │       └─ 已变 → 移除旧规则，生成新规则            │
  │    5. 调用 #generateRuleFromColumnType()         │
  │    6. 添加到验证引擎                             │
  │    7. 更新映射表                                 │
  └────────────────────────────────────────────────┘
        │
        ↓
  更新 #lastSyncedConfig 快照
```

### 7.3 增量同步流程

```
syncColumn(col)
        │
        ↓
  1. 读取该列最新配置
  2. 与 #lastSyncedConfig.get(col) 比较
     ├─ 配置未变 → 直接返回
     └─ 配置已变 → 继续
  3. 移除该列旧的自动规则（如有）
  4. 生成新规则（如有约束且无手动规则）
  5. 更新映射表和快照
```

## 8. 冲突解决策略

### 8.1 手动规则 vs 自动规则

**原则：手动规则始终优先**

| 场景 | 处理方式 |
|------|---------|
| 列有手动 number 规则 + 列配置 min/max | **不生成**自动规则，手动规则生效 |
| 列有手动 list 规则 + 列配置 source | **不生成**自动规则，手动规则生效 |
| 列有手动 number 规则 + 列配置 source | **生成**自动 list 规则（类型不同，不冲突） |
| 列有手动 date 规则 + 列配置 min/max | **不生成**自动规则，手动规则生效 |

### 8.2 去重判定逻辑

```javascript
#hasManualRuleForColumn(col, validationType) {
    const rules = this.#validationPlugin.getRulesForCell(0, col);
    return rules.some(rule =>
        rule.type === validationType &&
        rule.metadata?.source !== 'column-type-bridge'  // 排除自动规则
    );
}
```

### 8.3 优先级设计

```javascript
// 自动生成的规则优先级
const AUTO_RULE_PRIORITY = 1000;

// 用户手动设置的规则默认优先级
const MANUAL_RULE_DEFAULT_PRIORITY = 0;

// 效果：手动规则 (priority=0) 先执行，自动规则 (priority=1000) 后执行
// 短路策略下，手动规则失败即停止，自动规则不会被执行
```

### 8.4 移除手动规则后的回补

当用户移除手动规则后，桥接器应检测到该列不再有手动规则，自动补充生成规则：

```javascript
// 在 DataValidationPlugin.removeValidation() 后触发
bridge.onManualRuleRemoved(col, validationType);
// → 检查列配置是否有约束
// → 有约束且无其他手动规则 → 生成自动规则
```

## 9. 列类型约束提取规格

### 9.1 NumericColumnType 约束提取

```javascript
#extractNumericConstraints(options) {
    const constraints = {};
    if (options.min !== undefined && options.min !== null) {
        constraints.min = options.min;
    }
    if (options.max !== undefined && options.max !== null) {
        constraints.max = options.max;
    }
    return constraints;
}
```

**注意**：`numericFormat`、`allowInvalid` 不映射到验证规则（格式化是显示层概念，allowInvalid 是编辑器层概念）。

### 9.2 SelectColumnType 约束提取

```javascript
#extractSelectConstraints(options) {
    if (!options.source || !Array.isArray(options.source) || options.source.length === 0) {
        return null;
    }

    // 对象数组：提取 value 列表
    if (typeof options.source[0] === 'object' && options.source[0] !== null && 'value' in options.source[0]) {
        return { source: options.source.map(item => item.value).filter(v => v !== undefined && v !== null) };
    }

    // 简单数组：直接使用
    return { source: [...options.source] };
}
```

**注意**：`allowInvalid`、`strict` 不映射到验证规则（这些是编辑器层行为控制）。

### 9.3 DateColumnType 约束提取

```javascript
#extractDateConstraints(options) {
    const constraints = {};
    const pattern = options.dateFormat?.pattern || 'YYYY-MM-DD';
    const isTimeOnly = /^[Hhms: ]+$/.test(pattern);

    if (isTimeOnly) {
        // 纯时间模式 → 映射到 time 验证类型
        constraints.validationType = 'time';
    } else {
        constraints.validationType = 'date';
    }

    if (options.min !== undefined && options.min !== null) {
        constraints.min = options.min;
    }
    if (options.max !== undefined && options.max !== null) {
        constraints.max = options.max;
    }
    return constraints;
}
```

### 9.4 TextColumnType / TextareaColumnType 约束提取

```javascript
#extractTextConstraints(options) {
    if (options.maxLength !== undefined && options.maxLength !== null) {
        return { maxLength: options.maxLength };
    }
    return null;
}
```

### 11.3 列类型验证的降级处理

桥接激活后，列类型的 `validateCellValue()` 仍保留用于编辑器层的即时反馈（输入时红色边框），但**不再阻止提交**：

```javascript
// validateCellValue 的行为调整（通过桥接器控制）
validateCellValue(r, c, value) {
    const cellType = this.getCellTypeInstance(r, c);
    const result = validateCellValueInternal(cellType, value, this.#columnsConfig.get(c));

    // 桥接激活时：列类型验证仅作提示，不阻止
    // 阻止逻辑由 DataValidationPlugin 的钩子统一处理
    if (this.#bridge?.active && result !== true) {
        // 返回 "invalid" 而非 false，允许编辑器提交
        // 验证插件会在钩子层做最终拦截
        return typeof result === 'string' ? result : 'invalid';
    }

    return result;
}
```

### 12.1 同步开销

通过 `#lastSyncedConfig` 快照对比，避免配置未变时的重复生成：

```javascript
syncColumn(col) {
    const currentConfig = this.#columnTypeManager.getColumnConfig(col);
    const lastConfig = this.#lastSyncedConfig.get(col);

    // 深度比较约束相关字段
    if (this.#constraintEqual(currentConfig, lastConfig)) {
        return;  // 配置未变，跳过
    }

    // ... 执行同步 ...
}
```

- `#autoRuleToColumn`：每列一条映射，< 100 条
- `#columnToAutoRule`：每列一条映射，< 100 条
- `#lastSyncedConfig`：每列一份配置快照，< 100 份

## 15. 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 列配置频繁变更导致规则频繁重建 | 性能 | 低 | 增量同步 + 快照对比 + 防抖 |
| 对象数组 source 提取 value 后丢失 label 信息 | 下拉显示 | 中 | 自动规则保留原始 source 引用，UI 层从列类型获取 label |
| 手动规则与自动规则类型相同但约束不同 | 语义混淆 | 中 | 文档明确说明手动优先，UI 层提示"已有手动规则" |
| 桥接器初始化时序问题（验证插件未就绪） | 功能异常 | 低 | 桥接器在验证插件 init 完成后激活 |
| date 列纯时间模式 → time 验证类型映射不完整 | 验证失败 | 中 | TimeValidator 需支持与 DateColumnType 相同的格式 |
| 列配置使用函数式配置 `config = fn(col)` | 解析失败 | 低 | 桥接器在 applyColumnsConfig 解析后读取已解析的 columnsConfig |
