✨ 核心特性

直传模式
validation 子对象
在 columns 配置中直接声明验证规则，桥接器自动同步到 ValidationEngine
{ type: "numeric", validation: { type: "number", operator: "between", value: [0, 100] } }
向后兼容
options 推断模式
无 validation 时，桥接器从 type + options 自动推断验证规则
{ type: "numeric", options: { min: 0, max: 100 } } // → 自动推断 number between [0,100]
安全降级
插件未启用兜底
DataValidationPlugin 未启用时，列类型 validate() 兜底，仍可阻止无效值
// 无插件时： validateCellValue(r, c, val) → 列类型 validate() 正常阻止 // 有插件时： validateCellValue(r, c, val) → 降级为仅提示，插件统一拦截
手动优先
手动规则优先级
pluginOptions.rules 中的手动规则优先级高于自动生成的规则
// 手动规则 priority: 0 // 自动规则 priority: 1000 // 手动规则优先执行
增量同步
配置变更自动同步
columns 配置变更时，桥接器增量同步验证规则，未变更列跳过
sheet.applyColumnsConfig(newCols) → COLUMN_CONFIG_CHANGED 事件 → bridge.syncFromColumnConfig()
序列化排除
自动规则不导出
exportRules() 自动排除桥接器生成的规则，避免重复（可从列配置重建）
plugin.exportRules() // → 仅返回手动规则 // 自动规则从 columns 重建

⚡ 冲突解决机制

当 pluginOptions.dataValidation.rules 中的手动规则 与 columns[].validation 产生的自动规则 覆盖同一列的同类验证时，存在两层冲突解决机制：

第一层
规则注册阶段 — 手动优先，跳过自动
桥接器在 syncColumn() 时检测同列是否已存在同类型的手动规则 （metadata.source !== "column-validation"）。 若存在，跳过自动规则注册，仅标记 markBridgeTaken。
if (respectManualRules && hasManualRuleForColumn(col, rule.type)) { markBridgeTaken(col); // 仍标记桥接接管 return; // 不注册自动规则 }
第二层
验证执行阶段 — conflictStrategy
当同列存在多条不同类型规则时（如手动 list + 自动 number）， 由 conflictStrategy 决定多规则执行顺序。
conflictStrategy: "short-circuit" // 首条失败即返回 conflictStrategy: "priority" // 最后一条结果覆盖 conflictStrategy: "aggregate" // 收集所有错误合并

🧩 三种 conflictStrategy 行为对比

策略 行为 适用场景 优先级排序
short-circuit 按优先级从小到大执行，首条失败立即返回，不再检查后续规则 快速拦截，性能最优（默认） priority 0 → 1000
priority 按优先级从小到大执行，最后一条规则结果覆盖前面所有结果 高优先级规则拥有最终决定权 priority 0 → 1000
aggregate 执行所有规则，将所有错误消息用 ; 合并返回 需要展示所有违规信息 全部执行

📌 优先级体系

0
手动规则（pluginOptions.rules） 手动
用户在 pluginOptions.dataValidation.rules 中显式声明，priority 默认为 0
▼
1000
自动规则（桥接器生成） 自动
从 columns[].validation 或 type+options 推断生成，priority 固定为 1000

🔄 冲突场景与解决结果

场景 配置 解决方式 最终生效规则
A 同列同类：手动 number between [0,50] + 列配置 validation: { number between [0,100] } 第一层：桥接器检测到同列已有手动 number 规则 → 跳过自动规则注册 手动 number [0,50]
B 同列异类：手动 list 规则 + 列配置 validation: { number between [0,100] } 第一层：类型不同(list≠number) → 自动规则正常注册
第二层：两条规则按 conflictStrategy 执行 		手动 list + 自动 number
C 仅自动：列配置 validation: { number between [0,100] }，无手动规则 桥接器正常注册自动规则 自动 number [0,100]
D 手动规则被移除：原场景 A 中手动规则被 removeRule() 桥接器 onManualRuleRemoved() 自动回补自动规则 自动 number [0,100]（回补）
E 关闭手动优先：bridgeOptions: { respectManualRules: false } 桥接器不检查手动规则，自动规则始终注册（可能同列同类双规则） 手动 + 自动 共存
