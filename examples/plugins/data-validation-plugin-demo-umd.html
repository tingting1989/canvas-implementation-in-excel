🧮 公式验证示例 (17个) - 同步 vs 异步

📖 核心概念

同步验证 (🔄 errorStyle:'stop'): 使用轻量级解析器，支持基础运算符和简单函数（AND/OR/NOT/LEN/INT/DATE等），<16ms 响应，可立即阻止非法输入。

异步验证 (⏳ errorStyle:'warning'): 使用完整 FormulaEngine + ShadowEvaluator 沙箱，支持所有49个内置函数（SUM/AVERAGE/VLOOKUP/COUNTIF/IFERROR等），后台执行后显示标记。

🗓️ 日期验证特殊处理

当公式包含 DATE() 函数时， 系统会自动将 YYYY-MM-DD 格式的字符串转换为时间戳数字进行比较：

  • ✅ 输入："2024-06-15" → 转换：1718409600000 → 比较：1704067200000 ≤ 1718409600000 ≤ 1735689600000
  • ❌ 输入："2023-01-01" → 转换：1672531200000 → 比较失败：< 1704067200000
  • 🔧 支持格式：YYYY-MM-DD, YYYY/MM/DD, 或 JavaScript Date 对象
  • ⚠️ 注意：非标准格式（如"2024年6月15日"）需要预处理或使用异步验证

🔒 布尔值严格类型检查

当公式与 TRUE 或 FALSE 比较时， 系统会使用严格相等（===）运算符，禁止 JavaScript 的类型转换陷阱：

  • ✅ 通过：true (布尔值), false (布尔值)
  • ❌ 阻止：0, 1 (数字 - 即使语义相似也不通过)
  • ❌ 阻止："true", "false", "yes", "no" (字符串)
  • ❌ 阻止：null, undefined, "", [] (其他 falsy 值)
🔧 技术细节：
• JavaScript 宽松相等：0 == false → true（危险）
• 严格相等修复：0 === false → false（安全）
• 类型检查优先：typeof 不匹配直接返回 false

🔬 FormulaValidator 深度解析（沙箱隔离机制）

🛡️ 零副作用公式求值引擎

FormulaValidator 是数据验证插件的核心组件，专门用于执行自定义公式验证。 它采用沙箱隔离架构，确保公式求值过程完全独立于工作簿的主数据流， 不会产生任何副作用（side-effects）。

✅ 五大零副作用保证

  • 不调用 setVirtualCell
    不修改虚拟单元格状态
  • 不修改 DependencyGraph
    不影响依赖关系图结构
  • 不触发 AFTER_CALC 钩子
    无副作用通知事件
  • 不写入任何 Cache
    不污染计算缓存层
  • 求值结束后完全清理
    沙箱实例立即销毁

🎯 三层降级策略

  • P1: evaluateForValidation()
    FormulaEngine 专用验证接口（推荐）
  • P2: ShadowEvaluator 实例
    创建临时沙箱实例进行隔离求值
  • Fallback: 明确错误抛出
    拒绝使用有副作用的降级方案
  • ⚠️ 安全原则：宁可失败也不破坏数据完整性

📐 支持的公式语法

  • 比较运算: >, <, >=, <=, =, <>
  • 逻辑函数: AND(), OR(), NOT(), IF(), XOR()
  • 数学函数: SUM(), AVG(), MIN(), MAX(), ABS()
  • 文本函数: LEN(), LEFT(), RIGHT(), CONCAT(), TRIM()
  • 日期函数: DATE(), TODAY(), NOW(), YEAR(), MONTH()
  • 单元格引用: A1, B2, {row}, {col} 占位符

  errorStyle: 'warning'
}

说明：同时检查数值大于 0 且小于 100， 使用 AND() 函数组合两个条件。适用于成绩、百分比等有明确范围的场景。

📝 场景 2：文本长度验证

{
  range: 'K2:K20',
  type: 'formula',
  formula: '=LEN(K{row})>=5',
  errorMessage: '文本长度不足，需要 >= 5 个字符'
}

说明：使用 LEN() 函数检查文本长度， 确保用户输入满足最小字符数要求。适用于标题、描述等字段。

📅 场景 3：日期范围限制

{
  range: 'L2:L20',
  type: 'formula',
  formula: '=AND(L{row}>=DATE(2024,1,1), L{row}<=DATE(2024,12,31))',
  errorMessage: '日期必须在 2024 年内',
  errorStyle: 'stop'  // 阻止模式
}

说明：结合 DATE() 函数和 AND() 条件， 强制日期必须在指定年份范围内。errorStyle 设为 'stop' 可阻止无效输入。

🔄 场景 4：跨列逻辑条件

{
  range: 'J2:J20',
  type: 'formula',
  formula: '=OR(J{row}=TRUE, I{row}>50)',
  errorMessage: '需要为 TRUE 或 I列数值 > 50'
}

说明：使用 OR() 函数实现"或"逻辑， 引用多列数据进行复合判断。适用于审批状态、VIP 标识等业务规则。

📖 插件 API 参考

初始化
plugins 配置方式
plugins: ['dataValidation']
在 Workbook 构造时通过 plugins 数组启用数据验证插件，可通过 pluginOptions.dataValidation 传入初始规则。
new Workbook(canvas, { plugins: ['dataValidation'], pluginOptions: { dataValidation: { rules: [{ range: 'A:A', type: 'number', operator: 'greaterThan', value: 0 }], conflictStrategy: 'short-circuit' } } });
自定义公式验证
FormulaValidator（沙箱隔离）
type: 'formula' + formula 配置
使用 FormulaValidator 执行自定义公式验证，采用沙箱隔离机制确保零副作用：

核心特性：
• 🔒 沙箱隔离：不修改 DependencyGraph、Cache、触发钩子
• 🎯 专用接口：优先使用 evaluateForValidation()，降级使用 ShadowEvaluator
• ⚡ 零副作用：求值结束后无任何残留影响
• 🛡️ 错误边界：公式错误返回友好提示而非崩溃

占位符支持：
• {row} - 当前行号（自动替换为实际行号）
• {col} - 当前列号（自动替换为实际列号）
// 基础：值大于零 { range: 'I2:I20', type: 'formula', formula: '=I{row}>0', errorMessage: '必须大于 0' } // 复合条件：范围检查 { range: 'I2:I20', type: 'formula', formula: '=AND(I{row}>0, I{row}<100)', errorMessage: '必须在 0-100 范围内' } // 文本长度验证 { range: 'K2:K20', type: 'formula', formula: '=LEN(K{row})>=5', errorMessage: '文本长度不足' } // 日期范围验证 { range: 'L2:L20', type: 'formula', formula: '=AND(L{row}>=DATE(2024,1,1), L{row}<=DATE(2024,12,31))', errorMessage: '日期超出范围', errorStyle: 'stop' // 阻止模式 } // 复合逻辑条件 { range: 'J2:J20', type: 'formula', formula: '=OR(J{row}=TRUE, I{row}>50)', errorMessage: '复合条件不满足' }
规则管理
setValidation
dv.setValidation(ruleOptions): string
添加验证规则，返回规则 ID。触发 BEFORE/AFTER_VALIDATION_RULE_CHANGE 钩子。
const id = dv.setValidation({ range: 'B2:B100', type: 'number', operator: 'between', value: [0, 10000], errorMessage: '请输入0-10000', errorStyle: 'stop', allowBlank: true });
规则管理
removeValidation
dv.removeValidation(ruleId): boolean
根据规则 ID 移除验证规则，返回是否成功。
dv.removeValidation(id); // true
规则管理
getRulesForCell / getAllRules / getRuleById
dv.getRulesForCell(row, col): Rule[]
查询规则：按单元格查询、获取全部、按 ID 查询。
dv.getRulesForCell(0, 0); dv.getAllRules(); dv.getRuleById('vr_xxx');
验证执行
validateCell
dv.validateCell(row, col, value): Promise<Result>
异步验证单个单元格的值，返回 ValidationResult 对象。
const r = await dv.validateCell(0, 0, 50); // r.valid, r.message, r.errorStyle
验证执行
validateRange
dv.validateRange(range): Promise<Report>
批量验证区域内所有单元格，返回统计报告。
const report = await dv.validateRange('A1:A100'); // report.total, report.valid, // report.invalid, report.results
导入导出
exportRules / importRules
dv.exportRules(): Object[]
导出规则为 JSON 数组（持久化），或从 JSON 数组导入规则。
const json = dv.exportRules(); localStorage.setItem('dv', JSON.stringify(json)); const ids = dv.importRules(json);
生命周期
enable / disable / destroy
dv.enable() / dv.disable() / dv.destroy()
启用/禁用/销毁插件。禁用时暂停拦截，销毁时释放所有资源。
dv.disable(); // 暂停验证 dv.enable(); // 恢复验证 dv.destroy(); // 彻底销毁
冲突策略
engine.conflictStrategy
dv.engine.conflictStrategy = 'short-circuit'
设置多规则冲突解决策略：short-circuit（首条失败即返回）、priority（末条决定）、aggregate（收集全部错误）。
dv.engine.conflictStrategy = 'aggregate';
Hooks 事件
BEFORE_VALIDATE
hooks.runHooksUntil('beforeValidate', value, {row, col})
单元格验证前触发，返回 false 可拦截验证（阻止赋值）。参数：value（待验证值）、context（含 row, col）。
dv.hooks.addHook('beforeValidate', (value, ctx) => { console.log('验证前', value, ctx); });
Hooks 事件
AFTER_VALIDATE
hooks.runHooks('afterValidate', result)
单元格验证完成后触发。参数：result（ValidationResult 对象，含 valid, message, row, col, value, source）。
dv.hooks.addHook('afterValidate', (result) => { if (result.valid) console.log('通过'); });
Hooks 事件
VALIDATION_FAILED
hooks.runHooks('validationFailed', row, col, value, result)
验证失败时触发。参数：row, col（单元格位置）、value（输入值）、result（含 message, errorStyle）。
dv.hooks.addHook('validationFailed', (r, c, v, res) => { console.log('失败', res.message); });
Hooks 事件
BEFORE_VALIDATION_RULE_CHANGE
hooks.runHooksUntil('beforeValidationRuleChange', oldRule, newRule)
规则变更前触发（添加/删除规则），返回 false 可阻止变更。参数：oldRule（旧规则，添加时为 null）、newRule（新规则，删除时为 null）。
dv.hooks.addHook('beforeValidationRuleChange', (old, nw) => { console.log('规则即将变更'); });
Hooks 事件
AFTER_VALIDATION_RULE_CHANGE
hooks.runHooks('afterValidationRuleChange', newRule, oldRule)
规则变更后触发。参数：newRule（新规则，删除时为 null）、oldRule（旧规则，添加时为 null）。
dv.hooks.addHook('afterValidationRuleChange', (nw, old) => { console.log('规则已变更'); });
Hooks 事件
AFTER_BATCH_VALIDATION
hooks.runHooks('afterBatchValidation', report)
批量验证完成后触发。参数：report（含 total, valid, invalid, results 数组）。
dv.hooks.addHook('afterBatchValidation', (report) => { console.log('批量完成', report.total); });

⚙️ ValidationRule 配置项

必填
range + type
range: 'A1:A100', type: 'number'
range 指定目标区域（支持 "A:A" 整列、"1:1" 整行、"A1:B100" 区域）。type 指定验证类型。
条件
operator + value
operator: 'between', value: [0, 100]
operator 指定比较运算符，value 指定比较值。between/notBetween 时 value 为数组 [min, max]。
列表
source
source: ['选项A', '选项B']
type=list 时必填。静态数组或动态区域引用 '=Sheet1!$A$1:$A$10'。
正则
pattern
pattern: '^[a-z]+$'
type=regex 时必填。正则表达式字符串，也可使用 RegexValidator.PRESETS 中的预设名。
公式
formula
formula: '=A1>0'
type=formula 时必填。Excel 公式表达式（如 =AND(A1>0, A1<100)），返回真值表示验证通过。
错误提示
errorStyle + errorMessage
errorStyle: 'stop', errorMessage: '值无效'
errorStyle: stop（阻止输入）、warning（警告可继续）、information（仅提示）。errorMessage 自定义错误消息。
输入提示
inputMessage + inputTitle
inputMessage: '请输入正数', inputTitle: '提示'
选中单元格时显示的输入提示信息。
其他
allowBlank / showDropdown / priority
allowBlank: true, priority: 0
allowBlank 是否允许空值；showDropdown 是否显示下拉箭头（list 类型）；priority 规则优先级（越小越先执行）。
